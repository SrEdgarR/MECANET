## Modelo y privilegios

`recovery_runs` conserva fuente NORMAL y nuevo run RECOVERY separados; `admission_fence.recovery_id` selecciona exactamente uno. No fila o binding incorrecto significa cierre, nunca NORMAL implícito. Los campos de identidad del run son inmutables por trigger. Metadata central y local real está limitada a4096bytes/fila y el margen terminal central4096 se conserva dentro del presupuesto2MiB; los costes centrales incluyen ambos tipos nuevos. La reserva empresarial4352 se carga una sola vez al aplicar006 y `logical_usage()` la incluye con representación constante, sin reset de uso/reservas/contadores.

La migración central realiza sólo el ALTER de AdmissionFence y revocación de su privilegio antiguo como bootstrap, porque ese objeto tiene owner distinto. Las tablas/funciones nuevas pertenecen a `saas_owner` NOLOGIN. En cada DB local, el ejecutor es exclusivamente `saas_owner_a` o `saas_owner_b` NOLOGIN. Todos los search_path son fijos; PUBLIC no recibe EXECUTE. CREATE OR REPLACE conserva owner y ACL existentes; no se hace una revocación global sobre funciones de otros propietarios. [Contrato oficial CREATE FUNCTION](https://www.postgresql.org/docs/18/sql-createfunction.html), [ALTER TABLE](https://www.postgresql.org/docs/18/sql-altertable.html).

API sólo obtiene EXECUTE de dos observadores centrales, sin SELECT de registros de recuperación ni DML. `saas_writer_maintenance` tiene los observadores y SELECT de metadata técnica, y EXECUTE de funciones privadas fijas; se revoca su INSERT/UPDATE/DELETE libre L2, UPDATE de identidad/membership/grant/session/directory y UPDATE(admission_version). No obtiene credencial empresarial por ello. Cada `saas_maintainer_a/b` recibe sólo sus funciones/SELECT del singleton de su DB; no DML libre ni CONNECT ajeno. `saas_clock` sólo recibe adicionalmente el observador fijo de transferencia; conserva los privilegios previos de su CAS de reloj.

## Interfaces exactas del runtime

```sql
SELECT saas.recovery_runtime_guard($1::uuid,$2::uuid,$3::text) AS ready;
SELECT * FROM saas.recovery_service_state($1::uuid,$2::uuid,$3::text);
```

Argumentos: generation/runId/manifestHash de configuración privada. State devuelve únicamente mode, stage, generation, clock_owner UUID y clock_version/tick como text decimal, ready boolean. Getter central acotado: no abre pools empresariales, no devuelve cuerpos, refs, conteos, paths o IDs de tenants. El worker debe comprobar binding y stageCOMPLETE, no usar ready=false por cierre ordinario como prueba de modo RECOVERY. La respuesta HTTP pública sólo publica el booleano traducido al DTO aprobado.

Ready exige COMPLETE/barrera false/conjunto completo exacto/schema3/directorio-writer congruentes/reloj mismo owner y versiones/ticks concordantes. Permite cero empresas sólo si roster custodiado vacío coincide con el real. Permite B legítimamente CLOSED: NORMAL compara ACK vigente; RECOVERY usa también su fila SEALED RESTRICTED_CLOSED y el ACK histórico de la guarda fuente exacta, sin modificarlo al cambiar generation/epoch. Una operación ordinaria UNKNOWN no se elimina ni obliga por sí sola a ready503; un cierre pendiente sí lo hace. El observer físico del reloj conserva además el contrato de frescura de L1 en runtime.

```sql
SELECT saas.recovery_clock_guard(
 $1::uuid,$2::uuid,$3::text,$4::uuid,$5::uuid,$6::uuid,$7::text,$8::bigint,$9::bigint);
```

Argumentos: generation/run/manifest/previousOwner/nextOwner/transferId/transferHash/expectedClockVersion/expectedTick. EXEC sóloclock. Después se reconcilia el mismo owner y se registra el efecto; un reinicio real prepara otra transferencia tras fin positivo, nunca por antigüedad.
