Una intercepción que transporta una petición una sola vez debe tener un único responsable de ese débito, y debe impedir que además continúe la petición original. Un segundo envío real tiene otro débito; nunca se desactiva el contador para pérdidas de ACK. Solicitudes de origen o ruta no permitidos se rechazan antes del egreso y se contabilizan separadamente como bloqueadas. Sólo estados/códigos fijos/conteos/SHA se publican.

La UI actual usa como máximo cuatro intentos para ciertas lecturas `readJson` dentro de un contexto finito de8s; `getOnce` y las mutaciones tienen un solo intento. Deben contarse los intentos reales, no sólo respuestas2xx. Si hay503 y hace falta `Reintentar acceso`, se permite como máximo una acción manual dentro del plazo y respetando Retry-After; todos los HTTP adicionales permanecen en el mismo caso. No reenvío automático de POST ni sustitución de UUID. Las cuentas siguientes son estimaciones por código, no medición de capacidad ni autorización para llegar a un tope distinto.
